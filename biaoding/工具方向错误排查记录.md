# 工具方向错误排查记录

## 问题现象

YOLO 抓取时，机械臂运动到位，但**到达目标点上方的是末端法兰而非手掌**。无论怎么调整 `TOOL_TIP_LENGTH`（工具偏移长度），法兰始终停留在目标点附近，手掌无法到达预期抓取位置。

## 排查过程

### 第一步：怀疑 TOOL_TIP_LENGTH 值不对

法兰到掌心的距离测量为 13cm，代码中设置了 `TOOL_TIP_LENGTH = 0.13`。

- 将该值改为 `0.0` 测试，法兰目标位置确实发生了变化（Z 值从 0.66 变为 0.58，差约 8cm）。
- 但无论法兰移到哪个位置，**手掌就是不下去**。

**结论**：`TOOL_TIP_LENGTH` 值本身是对的，偏移量也在生效，但偏移的方向有问题。

### 第二步：排除控制器问题

通过诊断打印确认，movej 和 movel 之后控制器的实际 TCP 位置与代码计算的期望位置完全一致（偏差 0.0mm）。控制器执行正确。

**结论**：问题不在控制器，在于代码告诉控制器的目标位置本身就不对。

### 第三步：定位根因——TOOL_AXIS_DIR

原始代码（[yolo_grasp.py:78](yolo_grasp.py#L78)）：

```python
TOOL_AXIS_DIR = -V_UP_IN_BASE / np.linalg.norm(V_UP_IN_BASE)
```

这里**假设工具（手）从法兰沿"世界下方"方向延伸**（即手心朝下抓取时，手从法兰笔直向下伸）。

法兰位置的补偿计算：

```python
pre_flange  = pre_tip  - TOOL_TIP_LENGTH * TOOL_AXIS_DIR   # movej 目标
reach_flange = grasp_tip - TOOL_TIP_LENGTH * TOOL_AXIS_DIR  # movel 目标
```

即：`法兰 = 掌心目标 - L × 工具方向`。当 `TOOL_AXIS_DIR = 世界下方` 时，法兰实际被放在掌心**上方 L 处**，从而让掌心到位。

**实际装上 LinkerHand O6 后，手并不沿世界下方延伸**，而是沿**法兰自身的 Z 轴方向**。k 键示教时记录的法兰姿态（`grasp_rot`）显示法兰 Z 轴指向世界 +X 方向（侧面），而非世界下方。因此工具偏移被加在了错误的方向上，法兰没有正确后退，手掌自然到不了目标。

## 解决方案

将工具方向从硬编码的"世界下方"改为从示教姿态中读取的**真实法兰 Z 轴方向**：

```python
# 旧（错误）：
pre_flange = pre_tip - TOOL_TIP_LENGTH * TOOL_AXIS_DIR  # TOOL_AXIS_DIR = 世界下方（写死）

# 新（正确）：
tool_dir = self.grasp_rot[:, 2]     # 法兰 Z 轴在基座系下的真实方向
pre_flange = pre_tip - TOOL_TIP_LENGTH * tool_dir
```

对应的代码改动在 [yolo_grasp.py](yolo_grasp.py) 的 `grasp()` 方法中，movej 和 movel 两处法兰位置计算均使用 `tool_dir`。

## 经验教训

1. **不要假设工具的安装方向。** 手眼标定给出的是相机到法兰的关系，但手在法兰上的安装方向需要通过示教姿态的 FK 旋转矩阵获取。

2. **`TOOL_TIP_LENGTH` 本身不是问题**——改了它法兰位置确实会变，但如果偏移方向错了，改长度只是在错误的方向上移多移少，永远到不了正确位置。

3. **排查时先确认每个环节是否独立正确**：IK 解算 → movej 到位 → movel 到位 → 手掌位置。层层验证，定位到是"法兰到手掌的方向假设错误"这一环节。
