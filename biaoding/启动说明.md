## 一、视觉抓取测试（日常使用）

### 前提
- 手眼标定已完成，且 `biaoding/hand_eye_result.json` 是最新的（见第二部分）。

### 启动步骤

一键启动（推荐，自动按顺序起下面 3 项，每项间隔 2 秒，日志在 `biaoding/logs/`）：

```bash
~/Documents/elite_robot_ws/biaoding/start_grasp.sh
```

或手动分终端启动：

**终端1 — 机械臂驱动（无头模式）**

```bash
ros2 launch my_elite_robot_cell_control start_robot.launch.py headless_mode:=true launch_rviz:=false
```

**终端2 — ROS 相机**（开深度并与彩色对齐，目标点坐标优先从深度图读取）

```bash
ros2 launch realsense2_camera rs_launch.py \
  camera_namespace:=camera \
  enable_color:=true \
  enable_depth:=true \
  rgb_camera.color_profile:=1280x720x30 \
  depth_module.depth_profile:=640x480x30 \
  align_depth.enable:=true
```

**终端3 — 抓取测试**

```bash
cd ~/Documents/elite_robot_ws/biaoding
python3 visual_grasp_test.py
```

### 按键操作（在相机预览窗口上按）

| 按键 | 作用 |
|---|---|
| `G` | 视觉引导运动：检测标定板(ID=0) → 换算到基座坐标 → 沿世界系竖直方向抬高 `APPROACH_HEIGHT` → 控制器 movej 到预抓取点（法兰朝下） |
| `C` | 关闭夹爪 |
| `O` | 打开夹爪 |
| `H` | 回零位 |
| `Q` | 退出 |

### 注意
- 运动方式：**控制器原生 movej**（`/script_sender/script_command` 发脚本），不需要 move_group / grasp_move_server。IK 和轨迹规划在控制器内部完成，**无碰撞检查**。
- movej 走 def 主脚本会打断驱动的外部控制程序；脚本退出（Q）时自动调 `resend_external_script` 恢复。中途强杀（Ctrl+C 杀 python）后如需再用 MoveIt/轨迹控制，手动补一次：`ros2 service call /io_and_status_controller/resend_external_script std_srvs/srv/Trigger`。
- 倾斜安装补偿：基座前倾角度在脚本顶部 `TILT_ANGLE_DEG`（当前 45°），"目标点上方"指**世界系竖直上方**，不是基座 Z 上方。
- 终点姿态：`GRASP_ORIENTATION_MODE = "fixed_nearest"`（法兰朝下、自转角就近，避免手腕绕大圈）；夹爪朝向有要求时改 `"fixed"`。
- 坐标换算链路：相机检测标记 → `hand_eye_result.json`（相机→tool0）→ SDK 末端位姿（tool0→base）。**不依赖 TF，不需要启动 publish.launch.py**。
- 按 `G` 后看打印的"目标在基座坐标系"数值，和尺子实测对比，误差 ±1cm 内为正常。
- 偏差如果有固定方向，可调脚本开头的 `MANUAL_OFFSET_X/Y/Z` 补偿。
- 控制模式：标定/调试期间用示教器"本地"模式手动摆位没问题；要让脚本驱动机械臂运动，需确认机械臂处于可外部控制的状态（脚本报运动失败时先查这个）。
- 无头模式（headless_mode:=true）下**不要按示教器上的运动相关按钮，也不要再运行 cartesian_move 等 SDK 程序**——会覆盖驱动下发的控制脚本，导致机械臂接受指令却纹丝不动；被覆盖后用 `ros2 service call /io_and_status_controller/resend_external_script std_srvs/srv/Trigger` 恢复，或重启驱动。

## 二、手眼标定（easy_handeye2，带 rqt 界面）

标定只需做一次；相机拆装、支架松动后才需要重做。

### 启动步骤（按顺序开 4 个终端）

**终端1 — 机械臂驱动**

```bash
ros2 launch eli_cs_robot_driver elite_control.launch.py robot_ip:=192.168.1.212 cs_type:=cs66 local_ip:=192.168.1.102
```

**终端2 — RealSense 相机**

```bash
ros2 launch realsense2_camera rs_launch.py \
  camera_namespace:=camera \
  enable_color:=true \
  enable_depth:=false \
  rgb_camera.color_profile:=1280x720x30 \
  align_depth.enable:=false
```

**终端3 — ArUco 检测（发布标记 TF）**

```bash
cd ~/Documents/elite_robot_ws/biaoding
python3 aruco_single_tf.py
```

正常标志：打印 `Camera info received`，标记入镜后预览窗口有绿框+坐标轴，终端无警告刷屏。有警告时按警告内容排查（收不到图像 / 没有标记 / ID 不匹配）。

**终端4 — 标定服务 + rqt 界面**

```bash
ros2 launch easy_handeye2 elite_handeye_calibrate.launch.py
```

正常标志：终端打印 `All expected transforms are available on tf; ready to take samples`，并弹出 rqt 标定窗口。

### 采样要点（决定标定质量）

1. **每组之间末端必须旋转 20–30° 以上**，绕不同的轴转，同时挪位置、变距离（0.4–0.7m 为主）。
2. 每个采样位姿下标记(ID=0)必须完整出现在相机画面里。
3. 机械臂完全停稳、画面稳定后再点 **Take Sample**。
4. 采 15–25 组，然后点 **Compute Calibration**，确认数值合理后点 **Save Calibration**。

### 标定完成后：同步结果到抓取脚本

```bash
cd ~/Documents/elite_robot_ws/biaoding
python3 update_hand_eye_json.py
```

这一步把 `.calib` 转成 `hand_eye_result.json`。**每次重新标定后都必须跑一次**，否则抓取脚本用的还是旧结果。

### 标定验证（可选但推荐）

```bash
# 终端A：发布标定 TF（保持运行）
ros2 launch easy_handeye2 publish.launch.py name:=elite_cs66_handeye

# 终端B：观察标记在基座下的位姿
ros2 run tf2_ros tf2_echo base aruco_marker_frame
```

保持标记不动，用示教器把机械臂动到几个差别大的姿态：translation 各姿态间相差 **5mm 以内**为优秀，**1cm 左右**为当前硬件（D435@640x480 + 12.3cm 标记）的正常水平。

## 三、常见问题

| 现象 | 原因与处理 |
|---|---|
| rqt 窗口不弹出 | launch 文件改过没生效：`colcon build --packages-select easy_handeye2` 后重 source |
| handeye_server 一直刷 `Waiting for TF initialization` | 按提示缺的 TF 查：机器人侧看终端1，标记侧看终端3（标记要在视野内） |
| `tf2_echo` 报 `two unconnected trees` | publish.launch.py 没启动，或标定没 Save（检查 `.calib` 文件时间戳） |
| 抓取解算/运动失败 | 抓取脚本直接向控制器发 movej 脚本执行，目标不可达/IK 无解时控制器拒绝执行（看示教器报错），脚本等 30s 超时后打印提示。多为目标超工作空间：把目标放近一点；或确认机器人处于远程模式 |
| 驱动报 "Controller is not running"，或指令被接受但机械臂纹丝不动 | 机器人侧外部控制脚本没在跑。先查：`ros2 topic echo /io_and_status_controller/robot_task_running`（false 即没跑）。无头模式下确认：示教器处于"远程"模式、没人按过示教器运动按钮、没跑过 cartesian_move 等 SDK 程序。恢复：`ros2 service call /io_and_status_controller/resend_external_script std_srvs/srv/Trigger` 或重启驱动，任务恢复后 `controller_stopper` 会自动重新激活控制器 |
| 抓取偏差好几厘米 | `hand_eye_result.json` 不是最新的 → 跑 `update_hand_eye_json.py` |
| 想提高精度 | 相机改 1280x720、实测标记边长改 `aruco_single_tf.py` 的 `marker_size`、近距离采样，然后重标定 |

## 关键文件

| 文件 | 作用 |
|---|---|
| `~/.ros2/easy_handeye2/calibrations/elite_cs66_handeye.calib` | easy_handeye2 保存的标定结果 |
| `biaoding/hand_eye_result.json` | 抓取脚本实际读取的标定结果（由 update_hand_eye_json.py 生成） |

| `src/easy_handeye2/easy_handeye2/launch/elite_handeye_calibrate.launch.py` | 标定 launch（server + rqt 界面） |
