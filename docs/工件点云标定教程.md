# 工件点云标定教程（elite_polish_app）

> 适用：工件/治具挪位、换新工件后重标视觉定位。2026-08-09 实测定型。
> 相机动过/手眼重标过：先走 `biaoding/auto_hand_eye_calibration.py`，再进本教程。

## 一句话原理

拍照拿一帧点云 → 变换到 base 系 → 大盒裁出板子 → RANSAC 拟合板面 → 板心锚定原点 → 发布打磨参考系。标定就是给这条链路量 4 个参数：

| 参数 | 写在哪 | 数值从哪来 |
|---|---|---|
| `TOOL_Z` | `biaoding/grinder_tip.py:18` | 尺子量：法兰端面→砂盘接触面（不受压） |
| `curve_tool_offset` | yaml | = `TOOL_Z`（两处必须一致） |
| `target_box_min/max` | yaml | `analyze_ground_board.py` 自动算出 |
| `plane_point_o` | yaml | `analyze_ground_board.py` 算出的板心 x/y |

## 准备

- 四终端正常：驱动 → `scaled_joint_trajectory_controller` 激活 → 相机 → `elite_polish.launch.py`
- 速度 10~20%、手放急停、打磨机不接电
- **板子摆正固定后，全流程不能再动**

## 第 1 步：量工具长度

换过打磨头/砂盘/垫片才需要。尺子量法兰→砂盘面，改两处：

```python
# biaoding/grinder_tip.py:18
TOOL_Z = 0.183        # 实测值
```

yaml 里 `curve_tool_offset` 填同一个数（第 6 步一起改）。

## 第 2 步：碰板心

示教器把打磨头尖端轻触板面**物理中心**（尺子比着找，砂盘刚接触就停），手臂保持不动，另开终端：

```bash
python3 biaoding/grinder_tip.py
```

记下尖端坐标，例如 `(0.7598, -0.1915, 0.3846)`。碰得不太正中没关系（差 1~2cm 脚本会修正），但必须在板面上。

## 第 3 步：拍照留底

⚠ **先用示教器把手臂挪到拍照位**——命令 1 只拍下一帧，不动手臂；手臂压在板上拍出来的是废云。

```bash
ros2 topic pub --once /elite_vision_job_cmd std_msgs/msg/Int32 "data: 1"
cp /tmp/base.pcd /tmp/base_calib.pcd     # 留底，每次拍照都覆盖 base.pcd
```

`pcl_viewer /tmp/base_calib.pcd` 看一眼：板子完整、无打磨头。板面有反光空洞没事。

## 第 4 步：跑分析脚本（自动出盒子）

把第 2 步的尖端坐标填进脚本第 6 行：

```python
# biaoding/analyze_ground_board.py 第 6 行
TIP = np.array([0.7598, -0.1915, 0.3846])
```

```bash
python3 biaoding/analyze_ground_board.py
```

看输出，三个合格标准：

- `板面范围` 两个宽度 ≈ 板子实际尺寸（如 0.154 × 0.339m）——明显偏大 = 混进背景；
- `板心相对尖端偏移 du/dv` 的绝对值应 < 2cm（碰点偏多少它直接告诉你）；
- 建议盒内 `深层(d>15mm)` 杂物占比 < 2%。

全过 → 抄它打印的 `target_box_min/max` 和 `plane_point_o`（脚本给的是**实测板心**，比你手碰的准，直接用）。

## 第 5 步：填 yaml + 同步 install

`src/elite_polish_app/config/polish_params.yaml` 共 4 行：

```yaml
target_box_min: [0.706, -0.389, 0.317]   # 脚本输出
target_box_max: [0.832, -0.021, 0.559]   # 脚本输出
plane_point_o: [0.7690, -0.2057]         # 脚本输出的板心
curve_tool_offset: 0.183                 # 第 1 步的实测值
```

**必须同步 install（launch 读的是 install 的 yaml）：**

```bash
colcon build --packages-select elite_polish_app
```

## 第 6 步：全链路验证

```bash
ros2 launch elite_polish_app elite_polish.launch.py
# 确认手臂已挪离板子上方，再发：
ros2 topic pub --once /elite_vision_job_cmd std_msgs/msg/Int32 "data: 1"
```

盯日志，四层依次全绿才算完：

```text
target cloud size ≈4万 → [plane fit] OK → curve box cloud size ×万 → frame APPLIED
```

## 第 7 步：圆弧盒检查 + 终验

```bash
pcl_viewer curve_plane.pcd    # 工作空间根目录，视觉每次运行生成
```

- 只剩板面 → 不用动；看到地面/背景 → 对 `plane_trans.pcd` 做 z 切片找干扰带，调 `curve_box_min/max` 的 z（改了要重新同步 install + 重启 + 命令 1）；
- 空跑：`debug_skip_force_contact: true` 发命令 4，轨迹贴板不 REJECTED；
- 接触试跑：`debug_skip_force_contact: false`，打磨机不转；
- 真磨：接电，先小 `target_fz`。

## 换工件板（尺寸/弧度变了）要额外改什么

上面 7 步只管"板子在哪"。如果换的新板**尺寸或弧度也变了**，在 yaml 里追加改这些轨迹参数：

| 新板变化 | 参数 | 怎么定 |
|---|---|---|
| 长边（扫掠长度） | `polishcurve_start/end_ry_deg` | 扫掠长 = R·sin(ry)×2，按板长留 1cm 边（34.5cm 板 ≈ ±10.6°） |
| 短边（宽度） | `polishproduct_width` | 板宽留边（15.5cm 板取 0.15） |
| | `polishcurve_ycount` | 道间距 = width / ycount ≤ 砂盘直径（10cm 盘 → 7.5cm ✓） |
| | `curve_y_offset` | 打磨带在短边方向的居中位置，空跑看带偏了再调 |
| 弧面半径 R | `curve_radius` + `polishcurve_radius` | 两处必须一致；`curve_center_dz` / `polishcurve_center_dz` 配对改 |
| 只变厚度/高度 | 不用改 | 平面拟合自动跟新表面走；确认 `contact_max_travel`（0.25m）搜索距离够 |

覆盖够不够，空跑时看扫掠两端和上下边缘有没有磨到，再决定调 `ry_deg` / `width` / `curve_y_offset`。

## 坑（都是实测踩出来的）

| 坑 | 处理 |
|---|---|
| 发命令 1 时手臂压在板子上 | 命令 1 不动手臂！先挪到拍照位再拍 |
| 只改 src 的 yaml | 必须 `colcon build` 或 cp 到 install，否则重启还是旧参数 |
| 重启后没重新拍照 | 参考系只存内存，每次重启 launch 必须重发命令 1 |
| TOOL_Z 是旧工具的 | 尺量后 `grinder_tip.py` 和 `curve_tool_offset` 两处一起改 |
| 拍照和碰点之间挪了板子 | 全程不动；动了就从第 2 步重来 |
| 板面反光空洞 | 不影响，RANSAC 投票不怕洞 |

> 附：手动试框法（`pcd_box_tool.py --hist` + 逐格调整）已被第 4 步的脚本自动化，仅当脚本输出不合格、需要排查背景时才用，见《裁剪盒标定_手动单帧法.md》。
