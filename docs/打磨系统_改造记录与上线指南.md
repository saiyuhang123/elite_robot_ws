## 一、参数体系（重要背景）

所有可调参数集中在 **`src/elite_polish_app/config/polish_params.yaml`**，代码内默认值 = 当前标定值。

```bash
colcon build --packages-select elite_polish_app
# 或
cp src/elite_polish_app/config/polish_params.yaml install/elite_polish_app/share/elite_polish_app/config/
```

启动命令见 `src/elite_polish_app/启动命令.md`。

## 三、真机上真磨：要改的地方（按顺序）

### 3.1 开关类（必改）

| 参数 | 模拟值 | 真磨值 | 说明 |
|---|---|---|---|
| `debug_skip_force_contact` | true | **false** | 恢复 402 接触检测 + 404 力控 |
| `contact_fz_threshold` | -16.0 | 先 -6.0 试 | 接触判定阈值(N)，硬工件可回调大 |
| `target_fz` | -8.0 | 按工艺定 | 目标接触力，先保守（如 -5N）逐步加 |
| `adjust_dz` | 0.0003 | 先保守 | 力控步长，宁小勿大 |

### 3.2 示教类（必改）

- `home_q_deg` / `camera_capture_q_rad` / `polish_base_q_rad`：真工位重新示教（注意角度/弧度单位，参数名带后缀）。

### 3.3 工件与轨迹类（必改）

1. **裁剪盒四组**（`target_box_*`、`plane_point_*`、`plane_box_z_range`、`curve_box_*`）：
   按真工件+治具重新标定，方法任选：
   - 差分法：`pcd_diff.py`（空治具/有工件各拍一张，同一拍照位）；
   - 锚点法：打磨头碰面中心 → `grinder_tip.py` → PCA 拟合平面（本次墙上纸盒用的方法，最推荐）。
   ⚠ 三测点顺序：X 点必须在"离机器人更远"的位置，使法向指向工件内部，反了 IK 无解。
2. **圆弧/轨迹几何**：
   - `curve_radius` = `polishcurve_radius`、`curve_center_dz` = `polishcurve_center_dz`（**两处必须同步改**）——按真工件弧面半径；
   - `polishcurve_start_ry_deg` / `end_ry_deg`（扫掠角范围）、`polishproduct_width`（打磨宽度）、`polishcurve_ycount`（道数）；
   - `getCurveFrame` 的输出 = 平面系 × 圆弧偏移，真工件的圆弧特征位置重标。
3. **工具长度**：换打磨机/沙盘必须重测 `curve_tool_offset`（见 3.4）。

### 3.4 工具长度实测法（重要，复用）

```bash
# 1. 沙盘平贴工件表面（垂直轻贴）
# 2. ros2 run tf2_ros tf2_echo cs66_base_link cs66_tool0
# 3. 计算: 伸出长度 = 面内法向 · (面中心 - tool0位置)（本记录: 0.205m）
# 同时更新 biaoding/grinder_tip.py 的 TOOL_Z
```

### 3.5 硬件类

- 打磨机电源控制接**控制柜 DO0**，先命令 51/52 手动验证通断，再上全流程（403/405 步自动通断）。

### 3.6 验证清单（真磨前）

- [ ] 启动时机械臂静止无接触，去皮值 1~3N
- [ ] 大姿态变换后接触力读数漂移 < 2~3N（漂移大需查负载识别）
- [ ] 低速（10%）全流程跑通后再逐步提速
- [ ] 急停可用；首件旁边有人值守
- [ ] 力控接触段观察：压到工件后 force.z 应触发阈值，403 才允许开打磨机

### 3.7 可选优化（不阻塞）

- 25Hz 流式 action goal → 长期建议改流式接口（如 forward_position_controller）；
- AGV 残留 pub/sub 清理；
- 测点盒空/位置偏的运行时自动告警已有，可再加"定位结果合理性检查"（如法向与预期夹角）。

## 四、更换深度相机：要改的地方

### 4.1 点云话题（必改）

代码里写死订阅 `/camera/camera/depth/color/points`（`ysCamera3DSolver.cpp` 点云订阅处）。
推荐**不改代码**，在 launch 里做话题重映射：

```python
# elite_polish.launch.py 的 ysCamera3DSolver 节点加:
remappings=[('/camera/camera/depth/color/points', '/新相机/点云话题')]
```

### 4.2 点云格式（确认）

要求 `sensor_msgs/PointCloud2` 且含 x/y/z 字段（rgb 字段有无均可）。工业相机（Photoneo/Mech-Eye/Zivid/图漾等）
一般都直接提供；若只给自定义格式，需中间转换节点。点数门槛 `ysCamera3DSolver.cpp` 中
`if (eye_cloud_->size()<250000) return;`——新相机分辨率不同需调整该值。

### 4.3 手眼标定（必重做）

换相机/挪动相机位置都必须重新标定（`biaoding/auto_hand_eye_calibration.py`，aruco 方案已有），
然后把新结果填入 yaml 的 `handeye_rpy` / `handeye_translation`（不用改代码）。
验证：`grinder_tip.py` 碰标定板 + `pcd_box_tool.py` 查云，尖端与云片偏差 < 1cm。

### 4.4 标定重做

新相机视野/噪声特性不同，裁剪盒按第三节方法重标一遍；云质量变好后，
`pclCalcTransform.hpp` 里 `RadiusOutlierRemoval` 的两个参数（0.005/2、0.002/2）可适当放松。

### 4.5 如果新相机是眼在手外（固定安装）

当前点云变换是"FK(tool0) × 手眼"（相机在手臂上）。改固定相机后，点云回调里的
`ys_curP_eye_ = FK × 手眼` 要换成**固定的 base→相机变换**（base_link 系下静态标定），
即改成读一个静态变换参数，不再随关节角变化。这是唯一需要动代码逻辑的情形。

### 4.6 备选路线提醒

如果换相机是为了解决点云质量痛点，也可以考虑**三点示教法**（完全不用相机）：
示教器碰工件三点 → 算 planeFrame → × 预定义 curveFrame → 注入参考系。
此前已论证可行（见 `联调记录_2026-07-27.md`），相机故障时它也是降级备份方案。
