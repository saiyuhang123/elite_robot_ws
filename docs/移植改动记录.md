## 三、所有代码改动清单

### 3.1 新建：桥接节点 `elite_joint_trajectory_bridge.cpp`

**目的**：屏蔽 ysrob Topic 接口和 Elite Action 接口的差异，使状态机代码无需改动。

```
功能：订阅 /YsUR_driver/joint_trajectory (trajectory_msgs/JointTrajectory)
      → 转为 FollowJointTrajectory.Goal
      → 发送到 /scaled_joint_trajectory_controller/follow_joint_trajectory (Action)
```

**为什么这样做**：ysrob 状态机通过 publish JointTrajectory 到 Topic 来控制机器人，Elite 的 ros2_control 要求 Action 接口。加这个 50 行桥接节点后，状态机所有 `publish(traj_goal)` 代码保持不变。

以下替换应用到 `ysURForceAppControl.cpp`、`ysCamera3DSolver.cpp`、`ysURForceAppNode.cpp`、`ysCamera3DSolverNode.cpp`：

|---|---|---|
| `namespace ys_ur_robot` | `namespace elite_robot` | 避免与 ys_ur_driver 冲突 |
| `ys_prefix_ = "ys_"` | `ys_prefix_ = "cs66_"` | 适配 Elite 的 TF 命名约定 |
| `"shoulder_pan_joint"` 等6个裸关节名 | 不变，通过 `ys_prefix_ +` 拼接 | Elite 也用相同裸名 |

### 3.3 运动学链名称适配

**文件**：`ysURForceAppControl.cpp`

**改动前**：
```cpp
std::string ys_base = ys_prefix_ + "base";            // "ys_base"
ys_tip_link = ys_prefix_ + "kwr75";                    // "ys_kwr75"
ys_tip_link = ys_prefix_ + "polish_tool_tcp";          // "ys_polish_tool_tcp"
```

**改动后**：
```cpp
std::string ys_base = ys_prefix_ + "base_link";        // "cs66_base_link"
ys_tip_link = ys_prefix_ + "ft_frame";                  // "cs66_ft_frame"
ys_tip_link = ys_prefix_ + "tool0";                     // "cs66_tool0"
```

**原因**：
- UR5 URDF 的基座叫 `base`，Elite 叫 `base_link`
- UR5 用外部 KWR75 传感器（link 名 `kwr75`），Elite 用内置 F/T（link 名 `ft_frame`）
- 暂用 `tool0` 替代抛光工具 TCP，等打磨工具 URDF 加入后再改

### 3.4 ur_client_library 替换为 Elite GPIO

**文件**：`ysURForceAppControl.cpp`

**改动前** (ysPolishTool_Open/Close)：
```cpp
// 通过 UR Secondary 端口发 URScript 控制数字输出
std::unique_ptr<urcl::comm::URStream<...>> ur_secondary_stream;
ur_secondary_stream = std::make_unique<...>("192.168.2.201", ...);
auto program = "sec my_program():\n  set_digital_out(0, True)\nend\n";
ur_secondary_stream->write(data, len, written);
```

**改动后**：
```cpp
// 通过 Elite 的 IO controller ROS2 service 控制数字输出
auto client = node->create_client<eli_common_interface::srv::SetIO>(
    "/io_and_status_controller/set_io");
req->fun = SetIO::Request::FUN_SET_DIGITAL_OUT;
req->pin = 0;
req->state = 1.0;  // ON
client->async_send_request(req);
```

**原因**：Elite 不用 UR 协议，通过 ros2_control 的 GPIOController 的 SetIO service 控制 IO。

### 3.5 AGV 依赖清理

**文件**：`ysURForceAppControl.cpp`

改动3处：

1. **agv_goHomeCommand()**：不再发 WebSocket 命令，直接跳到下一步
2. **agv_WaitGoHomeDone()**：不再等待 AGV 回复，直接标记完成
3. **agv_goPolishCommand()**：同上，直接跳过
4. **agv_WaitGoPolishDone()**：同上，直接链到视觉步骤
5. **抛光完成后的自动操作**：`DO_AGV_GO_HOME` → `NOTHING`

**原因**：Elite 系统无 AGV，这些步骤需要立即跳过来保持状态机流转。

### 3.6 力传感器重力补偿清零

**文件**：`ysURForceAppControl.cpp`

**改动前**：
```cpp
ys_tool_gravity_ = KDL::Vector(-0.05, 0.19, -24.29);   // UR5 打磨工具 ~2.5kg
ys_tool_gcenter_ = KDL::Vector(0.025, -0.034, 0.046);   // UR5 工具质心
ys_bias_wrench_.force = KDL::Vector(-1.02, -3.25, 0.98); // UR5+KWR75 偏置
```

**改动后**：
```cpp
ys_tool_gravity_ = KDL::Vector(0.0, 0.0, 0.0);  // TODO: 装打磨工具后标定
ys_tool_gcenter_ = KDL::Vector(0.0, 0.0, 0.0);  // TODO: 装打磨工具后标定
ys_bias_wrench_.force = KDL::Vector(0.0, 0.0, 0.0); // 启动时自动标定200采样
```

**原因**：
- Elite 当前没装打磨工具，重力补偿应为 no-op
- 偏置（bias）会在启动后自动采集 200 个采样取平均，不需要硬编码

### 3.7 关节角替换为 Elite 占位值

**文件**：`ysURForceAppControl.cpp` — `initDataQ()`

**改动前**（UR5 关节角，单位：度）：
```cpp
ys_home_q_          = {88.96, -122.02, 98.92,  -66.39, -88.56, 135.91}
ys_cameraCapture_q_ = {42.35, -131.42, 102.08, -94.75, -57.66, 98.55}
ys_polishBase_q_    = {86.34, -105.52, 120.04, -162.39, -86.85, 135.04}
```

**改动后**（Elite 当前位姿，仅占位）：
```cpp
// TODO: ALL THREE POSES NEED TO BE RE-TAUGHT
ys_home_q_          = {8.2, -93.6, -109.4, 61.4, 86.4, -11.2}
ys_cameraCapture_q_ = {8.2, -93.6, -109.4, 61.4, 86.4, -11.2}
ys_polishBase_q_    = {8.2, -93.6, -109.4, 61.4, 86.4, -11.2}
```

**原因**：UR5 关节角对 CS66 完全无效且危险。暂用当前位姿作为安全占位值：三个命令（GO_HOME / 视觉拍照 / 打磨预备）都不会移动机器人。需要实际示教后才能使用。
