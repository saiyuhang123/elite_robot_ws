## 修复 1（P0）：`tr_camera` 链不存在导致状态机瘫痪 —— 改为代码内嵌手眼变换，不动 URDF

**背景**：原代码 KDL eye 链写死 `base_link → tr_camera`，而 URDF 中无 `tr_camera` link，`getChain` 失败 → `ys_eye_fk_solver_` 为 NULL → `timer_callback` 守卫永假，整个状态机（含 GO_HOME）不执行；视觉节点同理永不解算。

**方案选择**：曾考虑在 kybot URDF 中加固定关节，但因机器人描述文件较乱、不确定哪个生效，最终**回退 URDF 改动**（`kybot_elite_robot_cell_macro.xacro` 未做任何修改），改为在代码中把 KDL 链只到 `cs66_tool0`，手眼标定的固定变换（`tool0 → 相机光学系`）在使用处作为常量乘上。

**改动**：

- `src/elite_polish_app/src/ysURForceAppControl.cpp:146-153`
  eye 链 tip 由 `"tr_camera"` 改为 `ys_prefix_ + "tool0"`。
  说明：该节点中 eye FK 仅用于 `timer_callback` 守卫判断，不消费相机位姿，链到 tool0 即可。

- `src/elite_polish_app/src/ysCamera3DSolver.cpp:91-96`
  eye 链 tip 同样改为 `ys_prefix_ + "tool0"`（base 仍为 `cs66_base`）。

- `src/elite_polish_app/src/ysCamera3DSolver.cpp`（点云回调中）
  FK 得到 tool0 位姿后，乘上手眼标定固定变换再用于点云坐标变换：

  ```cpp
  static const KDL::Frame ys_T_tool0_camera_(
      KDL::Rotation::RPY(-0.063913, 0.009927, -1.552858),
      KDL::Vector(-0.135488, 0.025233, 0.033736));
  ys_curP_eye_ = ys_curP_eye_ * ys_T_tool0_camera_;
  ```

  数据来源：`biaoding/hand_eye_result.json` 的 `R_cam2tool` / `t_cam2tool`
  （`cv2.calibrateHandEye` 输出，即相机光学系在 tool0 系下的位姿；RPY 由 R_cam2tool 换算）。
  **若重新做手眼标定，必须同步更新这三行常量。**

**遗留验证（需相机+驱动在线）**：确认 `tr_camera`（= RealSense 点云光学系）与标定坐标系一致——机械臂动到已知姿态，对比代码 FK 结果与 RViz 中 RealSense TF。

## 修复 2（P0）：多点轨迹 `time_from_start` 相同被控制器静默拒绝

**背景**：ysrob 自研驱动自行插补、忽略时间戳；标准 `joint_trajectory_controller` 校验 `time_from_start` 单调递增，不满足直接 reject goal。

**改动**（均在 `src/elite_polish_app/src/ysURForceAppControl.cpp`）：

| 位置 | 原 | 改后 |
|---|---|---|
| `polish_goPolishBase` 第二点 | `= deltaT`（与第一点相同） | `= moveT + deltaT` |
| `polish_doForceContact` 循环点 | 全部 `= deltaT`（固定 8ms） | `= from_nanoseconds(deltaT.nanoseconds() * (i + 1))` |
| `polish_goBackHome` 循环点 | 全部 `= deltaT`（固定 20ms） | 同上，逐点递增 |
| `polish_goBackHome` home 点 | `= homeT`（2s·speed_level_，**早于**循环段终点 2.4s·speed_level_，同样会被拒） | `= from_nanoseconds(deltaT.nanoseconds() * trajCount) + homeT` |

单点轨迹（`vision_goCaptureMove`、`polish_doCurvePolishing`、`goHome_pubMoveHome`）不受影响，未改。

## 修复 3（P0 配套）：桥接节点补 `goal_response_callback`

**背景**：goal 被控制器 reject 时原来完全无感知，表现为"机械臂不动且无报错"。

**改动**：`src/elite_polish_app/src/elite_joint_trajectory_bridge.cpp`

- 新增 `goal_response_callback`：goal 被 REJECTED 时打 ERROR 日志。
- `result_callback` 中失败日志由 ERROR 降为 WARN（流式打磨时新 goal 抢占旧 goal，旧 goal 以 ABORTED 结束属预期行为，避免刷屏误导）。
