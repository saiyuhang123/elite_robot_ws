## 二、按时间线的排障过程

### 1. 命令 0 被 REJECTED
- 原因：`scaled_joint_trajectory_controller` 处于 inactive（非关节名问题）。
- 解决：`ros2 control set_controller_state scaled_joint_trajectory_controller active`。
- 注意：launch 默认参数本应自动激活，实际未生效，**每次重启驱动后要检查**。

### 2. 手眼变换验证（通过）
- 方法：打磨头尖端（tool z 伸出 18cm）抵标定板 → `biaoding/grinder_tip.py` 算尖端 base 系坐标 → `biaoding/pcd_box_tool.py` 查 `/tmp/base.pcd` 对应盒子。
- 结果：盒内 1089 点，尖端与云片偏差约 2mm。手眼标定 + FK 链 + 工具偏移三者自洽。

### 3. 点云质量问题
- D435 远处波浪噪声、temporal 滤波鬼影、边缘飞点。
- 对策：拍照距离 0.4~0.8m；关 temporal；threshold 滤波限 1.5m；裁剪盒负责最终隔离。
- 结论：算法吃质心/包围盒，对云质量要求不高。

### 4. 裁剪盒标定（反复失败多次）
- 开发了三个工具：`biaoding/pcd_box_tool.py`（离线模拟 CropBox + `--hist` 密度普查）、`biaoding/pcd_cluster.py`（连通域聚类）、`biaoding/pcd_diff.py`（空/有工件差分提取纯工件云）。
- **踩坑 1**：差分两张云必须同一拍照位拍摄（D435 深度误差随视角变，不同机位差分全是噪声）。
- **踩坑 2**：标定拍照位必须和命令 3 的拍照位一致（遮挡关系不同会导致测点盒空）。
- **踩坑 3**：纸箱（模拟工件）没固定，位置漂移导致标定反复失效。教训：**治具/定位标记是前提**。
- **踩坑 4（重要）**：三测点的**点序决定法向方向**。法向必须指向工件内部（远离机器人），反了则下压方向指向机器人自身 → IK 无解（rc=-3）。修正：X 测点放在离机器人更远处。
- **踩坑 5**：`getCurveFrame` 的 18cm 打磨头伸出补偿，**符号为 -0.18**（平面系 z 指向工件内部，法兰目标 = 表面 − 0.18×法向）。最初写成 +0.18 会把法兰送进工件。

### 5. 悬空狂晃事故（关键 bug）
- 现象：命令 3 后机械臂前移一段然后疯狂晃动（打磨头悬空未接触）。
- 根因：`polish_goPolishBase`（400 步）在 **IK 失败时仍把未初始化的 `ys_resultJnt` 打包发布**——垃圾关节角目标。
- 修复：IK 失败（rc!=1）或构型跳变（关节 1~5 >90°、wrist_3 >170°）时**中止流程不发布**。wrist_3 放宽是因为打磨头是旋转体。
- 教训：之后所有中止都安全、带日志。

### 6. 跳过视觉直接测打磨（命令 4）的三连坑
- **坑 A**：手动注入参考系（`/elite_vision_pose_broadcaster/pose`）不生效——原回调只在 sub_step==303 接收。加"空闲时接收"条件。
- **坑 B**：还是不生效——`app_cmd_` 启动初值是 **-1** 而非 NOTHING(99)，条件写成 `==NOTHING` 永不匹配。改为 `==NOTHING || <0`。症状：三次运行 resultJnt 完全相同（参考系从未应用）。
- **坑 C**：我自己算参考系的脚本位置项用错旋转矩阵（`T_R` vs `arc_R`），导致目标偏 46cm、IK 只能给远分支。修正后自验 upFrame == FK(polishBase)。
- 排查中排除的嫌疑：运动学不一致（0.3mm）、限位、关节映射、力符号、TRAC-IK 本身。

### 7. 全流程空跑成功
- 命令 4（`debug_skip_force_contact:=true`）：polishBase → 起点（=polishBase 姿态，分支差 0）→ 402 跳过 → 403 IO → 404 之字轨迹（1001 点连续执行）→ 405 IO → 406 退刀 → 回 Home。
- 轨迹形状：当前 `polishcurve_ycount_=1` 为单道弧面扫掠（ry ±9.2°）；之字形需 ycount≥2。
