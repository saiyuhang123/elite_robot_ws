# 打磨流程与坐标变换详解

> 对应代码：`src/elite_polish_app/`（从 ysrob 移植到 Elite CS66）
> 相关文档：`docs/移植方案_ysrob打磨到EliteCS66.md`、`docs/移植审查报告_elite_polish_app.md`、`docs/移植修复记录_2026-07-26.md`

## 一、坐标系清单

| 坐标系 | 含义 | 来源 |
|---|---|---|
| `cs66_base_link` | 机械臂基座系（45° 倾斜安装，一切计算的基准系） | URDF |
| `cs66_tool0` | 法兰系（物理末端） | URDF |
| `cs66_ft_frame` | 力传感器系（与 tool0 零偏移重合） | URDF |
| 相机光学系 | RealSense 点云所在坐标系（原 `tr_camera`，URDF 中不存在，代码内嵌变换） | RealSense 驱动 |
| 工件平面系（planeFrame） | 由三个测点拟合出的工件表面坐标系，**每次视觉现测** | 视觉计算 |
| 圆弧系（curveFrame） | 打磨圆弧特征的坐标系，在平面系下，**每次视觉现测**（仅平移） | 视觉计算 |
| 轨迹系 | 参数化打磨路径所在坐标系 = 圆弧系（写死的几何公式） | 代码参数 |

## 二、完整打磨流程

### 阶段 0：启动

1. 启动 Elite 驱动（自动激活 `scaled_joint_trajectory_controller`）、RealSense（开点云）、`elite_polish.launch.py`（桥接 + 状态机 + 视觉 + 命令节点）。
2. 状态机建三条 KDL 链（均从 URDF）：
   - `cs66_base_link → cs66_tool0`：TCP 正/逆解（TRAC-IK）
   - `cs66_base_link → cs66_ft_frame`：力传感器姿态（重力补偿、力坐标变换用）
   - `cs66_base_link → cs66_tool0`：eye 链（相机位姿；手眼固定变换在代码中另乘，见 3.1）
3. **力传感器去皮**：前 200 个力样本求平均存为 `ys_bias_wrench_`。要求启动时机械臂静止、打磨头无接触。

### 阶段 1：回 Home（命令 0）

示教关节角 `ys_home_q_` → 打包单点 JointTrajectory（joint_names 为 `cs66_` 前缀）→ 发 `/YsUR_driver/joint_trajectory` → **桥接节点**转 `FollowJointTrajectory` action → 控制器执行 → 关节角到位判断 → 完成。

### 阶段 2：视觉定位（命令 3）

1. 走到拍照位 `ys_cameraCapture_q_`；
2. 状态机发视觉命令 → `ysCamera3DSolver` 取一帧点云；
3. 点云从相机光学系转到 `cs66_base_link`（变换见 3.1）；
4. 三级裁剪定位（所有盒子坐标均人工标定写死，`pclCalcTransform.hpp`）：
   - **大盒** `getTargetCloud`：砍掉桌面/背景/机械臂本体，只留工件区域（纯减法，不做任何计算）；
   - **三测点小盒** `getPlaneFrame`：各取盒内点云中心 O/X/Y → 构造工件平面系（见 3.3）；
   - 点云转入平面系 → **圆弧盒** `getCurveCloud` 裁出弧面 → 求包围盒 → 算圆弧位置（见 3.5）；
5. 输出 `planeFrame × curveFrame`（PoseStamped）→ 状态机存为 `frame_polishcloud_transform_`（见 3.6）；
6. 自动链入命令 4。

### 阶段 3：力控打磨（命令 4，子步骤 400→407）

- **400 到打磨基准位**：先走 `ys_polishBase_q_`，再走到"轨迹起点 + tool z 抬高 `dz_polish_startup_tool_`"的预备点（见 3.8）；
- **402 力控接触**：沿 tool z 以 1mm 步进缓慢下压（每 40ms 一段轨迹），接触力 ≥ `target_fz_×2` 判接触成功，把位置偏差叠入力控基准（见 3.9）；
- **403 开打磨机**：SetIO 置控制柜 DO0 = 1；
- **404 之字形打磨**：每 40ms 一拍，三环串联（见 3.7）：
  - 目标位姿 = 力控微调 × 视觉参考系 × 参数化轨迹点[i]
  - TRAC-IK 逆解 → 发单点轨迹（新 goal 顶旧 goal）
  - 接触力与 `target_fz_` 偏差 > 3N 时沿 tool z 调 dz，叠进 `frame_forceadjust_base_`（见 3.10）
- **405 关打磨机**：DO0 = 0；
- **406 退刀回 Home**：base 系抬刀（**注意：该段按竖直基座硬编码，45° 倾斜安装需重调**，见 3.11）→ 回 Home；
- **407 到位** → 发完成结果 → 回 NOTHING。

## 三、代码中的全部坐标变换

### 3.1 手眼变换：tool0 → 相机光学系（代码内嵌常量）

位置：`ysCamera3DSolver.cpp`（点云回调）、`ysURForceAppControl.cpp:146-153`（链创建）

URDF 中无相机 link，KDL eye 链只到 `tool0`，手眼标定结果作为常量在使用处乘上：

```cpp
// 来源: biaoding/hand_eye_result.json（cv2.calibrateHandEye 的 R_cam2tool / t_cam2tool）
static const KDL::Frame ys_T_tool0_camera_(
    KDL::Rotation::RPY(-0.063913, 0.009927, -1.552858),
    KDL::Vector(-0.135488, 0.025233, 0.033736));
ys_curP_eye_ = ys_curP_eye_ * ys_T_tool0_camera_;   // 相机位姿 = FK(tool0) × 手眼
```

**重新做手眼标定后必须同步更新此常量。**

### 3.2 点云：相机光学系 → base_link

位置：`ysCamera3DSolver.cpp`（点云回调）

```cpp
ys_eye_fk_solver_->JntToCart(ys_cur_q_, ys_curP_eye_);   // base→tool0 的 FK
ys_curP_eye_ = ys_curP_eye_ * ys_T_tool0_camera_;        // 再乘手眼 → base→相机
pcl::transformPointCloud(*eye_cloud_, *base_cloud_, transform);  // 整云变换
```

之后所有 PCL 处理（裁剪盒、测点、拟合）都在 `cs66_base_link` 系下进行。

### 3.3 平面系构造：三个测点 → planeFrame（在 base_link 系下）

位置：`pclCalcTransform.hpp` `getPlaneFrame()`

三个测点小盒（写死的 base_link 系坐标）各取盒内点云（先 RadiusOutlierRemoval 去噪）的包围盒中心：

```cpp
x轴 = normalize(X - O)
z轴 = normalize(x轴 × (Y - O))     // 平面法向
y轴 = z轴 × x轴
planeFrame_ = Translation(O) × Rotation(x, y, z)
```

**工件的位置 + 姿态信息全部浓缩在 planeFrame_ 里**——这是视觉自适应摆放偏差的核心。

### 3.4 点云：base_link → 平面系

位置：`pclCalcTransform.hpp` `getPlaneCloud()`

```cpp
pcl::transformPointCloud(*targetCloud_, *planeCloud_, planeFrame_.inverse());
```

关键设计：**圆弧盒是在平面系（工件自己的坐标系）里裁剪的**，所以圆弧盒坐标虽写死，却能跟着工件走。

### 3.5 圆弧系：curveFrame（在平面系下，仅平移）

位置：`pclCalcTransform.hpp` `getCurveFrame()`

对圆弧盒内点云求包围盒 min/max/mid：

```cpp
trans(0) = mid.x;
trans(1) = max.y - 0.1;
trans(2) = min.z + 0.9306 - 1.89539;   // 0.9306/1.89539: 工件固有常数
curveFrame_ = Translation(trans)        // 无旋转
```

### 3.6 视觉输出：planeFrame × curveFrame → 状态机

位置：`pclCalcTransform.hpp` `calc()` → `ysCamera3DSolver.cpp`（发 PoseStamped）→ `ysURForceAppControl.cpp:350-364`（收）

```cpp
result = planeFrame_ * curveFrame_;     // 圆弧系在 base_link 下的完整位姿

// 状态机接收（topic: /elite_vision_pose_broadcaster/pose）:
frame_polishcloud_transform_.p = KDL::Vector(position...);
frame_polishcloud_transform_.M = KDL::Rotation::Quaternion(...);
```

### 3.7 核心变换串联：最终打磨目标位姿

位置：`ysURForceAppControl.cpp:1077`（`polish_doCurvePolishing`）

```cpp
tmpFrame = frame_forceadjust_base_        // ① 力控微调（base 系小偏移，打磨中实时累积）
         * frame_polishcloud_transform_   // ② 视觉现测：圆弧系在 base_link 下的位姿
         * polishcurve_OriginFrames_[i];  // ③ 写死的：第 i 个轨迹点在圆弧系下的位姿
// → tmpFrame: 当前这一拍工具在 base_link 系下的真实目标位姿
// → TRAC-IK 逆解 → 关节角 → 桥接 → 控制器
```

三层分工：**③ 路径是模具（启动时 `calcCurvePolishPath()` 一次性生成，含工具姿态 `RPY(0, ry, 0)` 贴合弧面法向 + `dirFrame = RPY(0,0,π)` 翻转），② 视觉决定模具往哪盖，① 力控决定盖章使多大劲。**

### 3.8 打磨预备点：轨迹起点 × tool z 抬高

位置：`ysURForceAppControl.cpp:768-771`（`polish_goPolishBase`）

```cpp
startPos = frame_polishcloud_transform_ * polishcurve_OriginFrames_[0];  // 轨迹起点
moveFrame.p = KDL::Vector(0, 0, dz_polish_startup_tool_);                // tool z 抬高量
upFrame = startPos * moveFrame;        // 右乘: 在工具自身坐标系内偏移
```

### 3.9 力控接触：沿 tool z 步进 + 接触后偏差记录

位置：`ysURForceAppControl.cpp:833-836, 917-922`（`polish_doForceContact`）

```cpp
curFrame = ys_curP_tcp_;  curFrame.M = startPos.M;      // 位置用当前，姿态锁定为目标姿态
moveFrame.p = KDL::Vector(0,0,dcontact) * (i+1)/trajCount;  // tool z 每步 1mm
tmpFrame = curFrame * moveFrame;                        // 右乘: 沿 tool z 下压

// 接触成功时，把"当前位置 - 轨迹起点位置"的偏差（base 系）叠入力控基准:
offsetFrame.p = curFrame.p - startPos.p;
frame_forceadjust_base_ = offsetFrame * frame_forceadjust_base_;
```

### 3.10 力控微调：tool z 的 dz → base 系

位置：`ysURForceAppControl.cpp:1052-1054`（`polish_doCurvePolishing`）

```cpp
offsetFrame.p = curFrame.M * KDL::Vector(0,0,dz);   // 关键: dz 定义在 tool 系，
                                                     // 用当前工具姿态旋转到 base 系
frame_forceadjust_base_ = offsetFrame * frame_forceadjust_base_;  // 左乘累积
```

接触力 > 目标 → dz 抬离；< 目标 → dz 下压；|偏差| < 3N → dz = 0（死区）。

### 3.11 退刀：base 系硬编码方向（⚠ 45° 倾斜需重调）

位置：`ysURForceAppControl.cpp:968-970`（`polish_goBackHome`）

```cpp
moveFrame.p = KDL::Vector(0, 0.1*(i+1)/trajCount, (0.4-curFrame.p.data[2])*(i+1)/trajCount);
upFrame = moveFrame * curFrame;    // 注意是左乘: 偏移直接定义在 base 系
// 含义: base y 方向退 0.1m，同时 base z 拉到 0.4m —— 按竖直安装基座写的"侧上方退刀"
// 45° 倾斜安装后 base z 不再是竖直方向，此段需按现场重调
```

### 3.12 力数据的坐标变换

位置：`ysURForceAppControl.cpp`（wrench 回调 / `ys_gravityRepairWrench`）

```cpp
// 重力补偿: 工具重力向量(base 系常量) → 旋转到当前传感器系
gravity_sensor = ys_curP_ftsensor_.M.Inverse() * ys_tool_gravity_;
value.force = data.force - gravity_sensor;          // 传感器系下扣重力
value.torque = data.torque - (gravity_sensor × 质心); // 扣重力矩(叉乘展开)

// 接触力: 传感器系 → base 系（仅供监控/调试用）
ys_contact_wrench_base_.force  = ys_curP_ftsensor_.M * sensor.force;
ys_contact_wrench_base_.torque = ys_curP_ftsensor_.M * sensor.torque;

// 力控实际使用: 传感器系下去偏置（力控方向是 tool z，天然在传感器/工具系，无需再转）
ys_contact_wrench_sensor_ = ys_gravityRepairWrench(data) - ys_bias_wrench_;
```

注意 URDF 中 `ft_frame`/`flange`/`tool0` 零偏移重合，所以"传感器系 = 工具系"成立，力控的 tool z 方向无需额外变换。

## 四、变换关系总图

```
                         cs66_base_link（一切计算的基准）
                        /        |          \
              FK(关节角)         |            FK(关节角)
                  |              |              |
              cs66_tool0    cs66_ft_frame       |
                  |         （力数据坐标变换      |
            × 手眼常量        见 3.12）          |
                  |                              |
             相机光学系 ── 点云 ──→ 转回 base_link（3.2）
                                         |
                              大盒裁剪（减法，不算位置）
                                         |
                    三测点小盒 → 拟合 planeFrame（3.3，工件位姿全在此）
                                         |
                       点云 × planeFrame⁻¹ → 平面系（3.4）
                                         |
                       圆弧盒 → curveFrame（3.5，仅平移）
                                         |
       视觉输出 = planeFrame × curveFrame = frame_polishcloud_transform_（3.6）
                                         |
   最终目标 = frame_forceadjust_base_（力控, 3.9/3.10）
           × frame_polishcloud_transform_（视觉）
           × polishcurve_OriginFrames_[i]（写死轨迹）
                                         |
                                   TRAC-IK 逆解 → 关节角 → 执行
```

**一句话：路径写死在圆弧系，视觉每次重测圆弧系在 base_link 下的位姿，力控在最外层叠实时微调，三者左到右相乘得到工具真实目标位姿。**
