# 裁剪盒标定（手动单帧法）

> 适用：`elite_polish_app` 视觉定位链路中的三层裁剪盒（大盒 / 三测点 / 圆弧盒）重标。
> 方法：拍照位拍一帧点云 + 打磨头碰板心拿一个精确面上点 + `pcd_box_tool` 探针手工圈盒。
> 不需要"空治具"差分帧；背景杂乱时建议改用差分法（见文末附录）。
> 换新打磨板的**完整流程**（工具长度/负载/安全限制/轨迹参数）见《新打磨板标定流程.md》。

---

## 1. 背景：裁剪盒标的是什么

视觉节点（ysCamera3DSolver）把相机点云变换到 `cs66_base_link` 后，用三层盒子逐级裁剪定位工件：

| 盒子 | 参数（polish_params.yaml） | 坐标系 | 作用 |
|---|---|---|---|
| 大盒 | `target_box_min/max` | base_link | 圈出工件整体，排除桌面/墙/机械臂 |
| 三测点 | `plane_point_o/x/y` + `plane_box_z_range` | base_link | 拟合工件平面系（法向=打磨头压入方向） |
| 圆弧盒 | `curve_box_min/max` | 工件平面系 | 圈出弧面特征，定位圆弧系（打磨轨迹的模具） |

裁剪盒标的是**工件在空间里的位置**，不是工具/打磨板。打磨板尺寸只影响轨迹参数（见第 7 节），不影响裁剪盒。

---

## 2. 什么时候必须重标

发生以下任一情况，三个盒全部要重走一遍：

1. **工件/治具挪过位置**（哪怕只是平移几厘米）；
2. **相机动了、换了相机或镜头**；
3. **手眼矩阵重新标定过**（base_link 点云 = 相机坐标 × 手眼矩阵，手眼一变坐标全变）。

判断旧盒是否失效：跑一次视觉命令，看 ysCamera3DSolver 日志。
`target cloud size` 明显变小、`plane measure box empty`、`curve box empty` 都是旧盒对不上的典型症状。

---

## 3. 前置条件

- 打磨系统四个终端正常启动（驱动 / 相机 / `elite_polish.launch.py`）；
- 低速、手放急停；打磨机不接电；
- 先确认手眼标定本身可信：`grinder_tip.py` 碰点 + 点云盒子法，质心 ≈ 尖端（<1cm）；
- 确认 `cloud_min_points` 门槛（Camport 约 23.7 万点，D435 约 40 万点）不会被当前云触发丢帧。

---

## 4. 标定步骤

### 4.1 拍一帧基准云并留底

```bash
ros2 topic pub --once /elite_vision_job_cmd std_msgs/msg/Int32 "data: 1"
cp /tmp/base.pcd /tmp/base_calib.pcd
```

- 命令 1 会自动：机械臂去拍照位 → 相机拍一帧 → 存 `/tmp/base.pcd`（base_link 系）；
- **每次拍照都会覆盖** `/tmp/base.pcd`，标定期间先复制留底；
- 工件位置一旦定下来就**不要再挪**，否则云和碰点对不上。

### 4.2 碰板心，拿 O 点

示教器慢速把打磨头尖端轻触**工件板面中心**，保持不动，另开终端：

```bash
python3 biaoding/grinder_tip.py
```

记下输出的尖端坐标 `(x, y, z)`，这就是三测点的 **O 点**。
验证 O 落在云面上（以 O 为中心 ±2cm 盒子应有点，质心≈尖端）：

```bash
python3 biaoding/pcd_box_tool.py /tmp/base_calib.pcd <x-0.02> <y-0.02> <z-0.02> <x+0.02> <y+0.02> <z+0.02>
```

> 若尖端与盒内质心偏差 >1cm，先排查 `grinder_tip.py` 的 `TOOL_Z` 是否与实物一致（换过打磨板/砂盘厚度后必须重测），再做下一步。

### 4.3 定大盒（6 个数）

```bash
python3 biaoding/pcd_box_tool.py /tmp/base_calib.pcd --hist     # 找工件密集区
python3 biaoding/pcd_box_tool.py /tmp/base_calib.pcd <xmin> <ymin> <zmin> <xmax> <ymax> <zmax>   # 试框
```

判断标准：

- 盒内**全是工件**，四壁比工件边缘宽 2~3cm；
- 盒内 min/max 某方向**顶到盒壁** → 切到工件了，该方向要放宽；
- 盒子外沿方向各探 4~6cm 一档，应基本为空（若有成片点，是背景/桌面，要收紧）。

背景贴近工件时（如墙面/桌面离工件只有几厘米），要精确卡在背景起点之前，参考 `--hist` 的密度分布逐层看。

### 4.4 定三测点 O / X / Y

- **O**：4.2 的碰板心坐标（x/y 用尖端值，z 由云自己算）；
- **X**：在云上找"**离机器人更远**"约 10cm 的面上位置（法向 = (X−O)×(Y−O) 必须指向工件内部，X 放错侧法向会反转）；
- **Y**：另一方向约 5~10cm 的面上位置（与 X 构成大三角）。

每个点用 ±5mm 小盒验证（z 方向用 `plane_box_z_range` 贯通工件面）：

```bash
python3 biaoding/pcd_box_tool.py /tmp/base_calib.pcd <px-0.005> <py-0.005> <zmin> <px+0.005> <py+0.005> <zmax>
```

每个盒至少几百点、质心在盒中心附近。`plane_box_z_range` 要罩住三个点所在的面（z 范围宽一点没关系，但别把桌子/背景圈进去）。

### 4.5 填 yaml（重点！src 和 install 都要改）

编辑 `src/elite_polish_app/config/polish_params.yaml`：

```yaml
target_box_min: [xmin, ymin, zmin]
target_box_max: [xmax, ymax, zmax]
plane_box_z_range: [zmin, zmax]
plane_point_o: [O.x, O.y]
plane_point_x: [X.x, X.y]
plane_point_y: [Y.x, Y.y]
```

**launch 实际加载的是 install 里的 yaml，不是 src！** 改完 src 必须同步：

```bash
# 方式一（推荐）：重编译
colcon build --packages-select elite_polish_app
# 方式二（快）：手动复制
cp src/elite_polish_app/config/polish_params.yaml \
   install/elite_polish_app/share/elite_polish_app/config/polish_params.yaml
```

不同步的典型症状：重启后日志里 `target cloud size` 数值和旧盒一致（不是新盒），测点 FAIL。

### 4.6 重启 + 拍照验证

```bash
ros2 launch elite_polish_app elite_polish.launch.py
ros2 topic pub --once /elite_vision_job_cmd std_msgs/msg/Int32 "data: 1"
```

盯 ysCamera3DSolver 日志，逐层确认：

```text
base cloud size  ××万
target cloud size ××万        ← 大盒生效
plane origin / x axis / y axis ← 三个测点非空，z 都落在工件面上
curve box cloud size ×万      ← 圆弧盒非空
curve frame bbox x/y/z        ← 只有弧面特征，无桌子/背景
frame APPLIED                 ← 参考系注入成功
```

任何一层 FAIL 就回头调对应盒，改完回到 4.5（要同步 install）。

### 4.7 圆弧盒：检查并调 z 范围

圆弧盒在**工件平面系**下，视觉节点每次运行会生成中间产物（相对路径，在 launch 的工作目录）：

```bash
ls -l plane_trans.pcd curve_plane.pcd   # 在 ~/Documents/elite_robot_ws 下
pcl_viewer curve_plane.pcd
```

- `curve_plane.pcd` 里**只能有弧面**。若看到桌子/背景，用 `pcd_box_tool.py` 对 `plane_trans.pcd` 做 z 切片（2~5mm 一格），找桌子带的 z 范围，把 `curve_box_min` 的 z 下限抬到桌子顶部之上；
- 同时用切片确认弧面顶部的 z，`curve_box_max` 的 z 上限要罩住弧面顶部（±2cm 的薄盒经常把弧面顶部切掉，导致定位偏）；
- x/y 范围比弧面实际 bbox 留 1~2cm 余量即可，太大容易圈进边缘背景。

---

## 5. 验证标准汇总

| 检查项 | 合格标准 |
|---|---|
| 大盒 | 盒内全是工件，四壁留 2~3cm；盒外探针基本为空 |
| 三测点 | 每个 ±5mm 盒几百点；质心在盒中心附近；三个 z 同在一个面上 |
| 法向 | (X−O)×(Y−O) 指向工件内部（打磨头压入方向） |
| 圆弧盒 | curve_plane.pcd 只剩弧面；bbox z 范围干净、罩住弧面顶部 |
| 视觉链路 | 日志各层非空、无 FAIL；`frame APPLIED` |
| 终验 | 命令 4 空跑：轨迹起点落在工件上、扫掠贴弧面、不撞不 REJECTED |

---

## 6. 常见坑

| 坑 | 现象 | 处理 |
|---|---|---|
| 只改 src yaml | 重启后跑的还是旧参数（target cloud 数值与旧盒一致） | src 改完必须 `colcon build` 或 cp 到 install |
| 工件在拍照和碰点之间挪动 | 尖端坐标不在云面上 | 位置定死后不要再动工件 |
| 换了打磨板没重测 tool 长度 | 尖端 vs 云面质心偏差 1~2cm | 重测 `TOOL_Z`（grinder_tip.py）和 `curve_tool_offset`（yaml），两处必须同步 |
| X 点方向放反 | 平面法向反转，姿态全错 | X 必须放在"离机器人更远"侧 |
| 桌子漏进圆弧盒 | curve_plane.pcd 底部有条窄带（平面系 z 负值、y 窄） | 抬 `curve_box_min` 的 z 下限 |
| 圆弧盒 z 上限太矮 | 弧面顶部被切，bbox z 顶到盒壁 | 用 plane_trans.pcd 切片确认弧面真实 z 范围，扩 z 上限 |
| `pcd_box_tool` 参数顺序 | 盒子形状不对 | 顺序是 xmin ymin zmin xmax ymax zmax |

## 7. 附：打磨板 34.5×15.5 对应的轨迹参数（与裁剪盒无关，但要一起确认）

| 参数 | 当前值 | 说明 |
|---|---|---|
| `polishproduct_width` | 0.12 | 板宽 15.5cm 留边取 12cm（打磨带 y 方向） |
| `polishcurve_start/end_ry_deg` | ±9.2° | 弧长 = 0.9306 × 18.4°×π/180 ≈ 29.9cm；若扫掠沿板长 34.5cm 且要全覆盖，改 ±10.6°（留 1cm 边 ±10.0°） |
| `curve_tool_offset` / `TOOL_Z` | 0.205 | 打磨头（含沙盘）沿 tool z 伸出长度，平贴实测；换板后必须重测，两处同步 |
| `polishcurve_ycount` | 3 | 打磨道数 |

轨迹覆盖是否够，在空跑时看弧面两端/上下边缘有没有磨到，再决定调宽度或 `curve_y_offset`。

## 8. 附：差分法（备选）

工件附近背景杂乱、大盒怎么框都会圈进背景时，用差分法自动分离工件：

```bash
# 拍照位不动：空治具一帧，有工件一帧
ros2 topic pub --once /elite_vision_job_cmd std_msgs/msg/Int32 "data: 1"
cp /tmp/base.pcd /tmp/empty.pcd
ros2 topic pub --once /elite_vision_job_cmd std_msgs/msg/Int32 "data: 1"
cp /tmp/base.pcd /tmp/with_part.pcd
python3 biaoding/pcd_diff.py        # 输出工件包围盒（含 2cm 余量）→ 填 target_box_*
```

其余步骤（三测点、圆弧盒、验证）与手动法相同。
