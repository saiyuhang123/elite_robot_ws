# 新打磨板标定流程（换板/换工具后全套）

> 适用：更换打磨板（或打磨机、砂盘）后，重新让打磨系统适配新工具。
> 裁剪盒详细步骤见《裁剪盒标定_手动单帧法.md》，本文是换板后的**完整清单**。
> 2026-08-01 实测整理（34.5×15.5 打磨板 + 10cm 打磨片 + 1.520kg 负载）。

---

## 0. 什么时候需要走这套流程

| 变更 | 需要重做的项 |
|---|---|
| 换打磨板/打磨机/砂盘 | 工具长度、负载/重力、轨迹参数（必）；裁剪盒（看板面是否动） |
| 工件/治具挪位 | 裁剪盒、参考系（必） |
| 换相机/手眼重标 | 手眼参数、裁剪盒（必） |

换打磨板**不需要**重标手眼，但以下每项都要核对，漏一项就会在试跑时暴露。

---

## 1. 物理准备

- 打磨板摆正（垂直）、**与支撑面留 5~10cm 间隙**——板底贴地会让地面点混进裁剪盒，标不准；
- 打磨机不接电；驱动端速度比例 10~20%；手放急停。

---

## 2. 工具长度实测（TOOL_Z / curve_tool_offset）

**为什么**：打磨头尖端位置 = tool0 + 沿 tool z 偏移 `TOOL_Z` 算出。换板后厚度/安装变化会让尖端算偏——实测偏差可达 1~3cm，直接影响接触。

**方法（二选一）**：

1. 平贴实测：打磨头尖端贴板面，记录 `grinder_tip.py` 输出的 tool0，量实际板面位置，反推真实长度；
2. 经验验证：碰板心后跑 `grinder_tip.py` + `pcd_box_tool`，如果盒内云面质心和尖端偏差 >1cm，`TOOL_Z` 大概率不对。

**同步修改（两处必须一致）**：

```bash
biaoding/grinder_tip.py          # TOOL_Z
src/elite_polish_app/config/polish_params.yaml   # curve_tool_offset
```

---

## 3. 示教器负载辨识 + 重力补偿参数

1. 示教器做**负载辨识**，记录：质量（kg）、质心 x/y/z；
2. 更新 yaml（ysURForceAppControl 段）：

```yaml
# 世界系向下在 base 系方向: (0.7431, -0.0120, -0.6691)
tool_gravity: [质量*9.81*0.7431, 质量*9.81*(-0.0120), 质量*9.81*(-0.6691)]
tool_gcenter: [-0.05632, 0.01936, -0.01986]   # 保持 7-27 传感器系值；示教器质心是法兰系，直接换会破坏力矩补偿
```

3. 验证：**多姿态**静止时 `/ys_contact_fts_broadcaster/wrench` 都应 ≈0（±1N）。只在一个姿态验证过不算数（实测打磨位姿残差可达 −23N，会污染接触判定和力控）。

> 注意：示教器负载辨识只做**当前姿态归零**，不是全姿态补偿，代码内的 `tool_gravity` 必须启用。
> 若多姿态残差仍大，用 `biaoding/fit_tool_gravity.py` 多姿态拟合（5 组姿态 + 原始力 + 关节角）。

---

## 4. 示教器安全限制（关键！）

真实接触必触发报警，除非先把安全限制调高：

```text
示教器 → 安全设置 → 碰撞检测 / 力 / 力矩限制 → 调到 30~50N
```

- 阈值过低（实测 2N 接触就报"末端传感器检测到碰撞"）时，任何打磨都无法进行；
- 报警**保持开启**，不要关着跑（关掉就没有碰撞保护了）。

---

## 5. 裁剪盒重标

按《裁剪盒标定_手动单帧法.md》完整走：大盒 → 三测点 → 圆弧盒。

重点检查：

- 圆弧盒 z 范围用 `plane_trans.pcd` / `curve_plane.pcd` 切片验证——排除地面/背景，且**别切掉弧面顶部**；
- 板底悬空后，大盒 z 下限和圆弧盒 z 下限可以收紧。

---

## 6. 轨迹参数（按板尺寸）

| 参数 | 当前参考值 | 说明 |
|---|---|---|
| `polishproduct_width` | 0.15 | = 工件宽 15cm |
| `polishcurve_ycount` | 2 | 道间距 = width/ycount ≤ 打磨片直径（10cm→7.5cm ✓） |
| `polishcurve_start/end_ry_deg` | ±9.2° | 直线模式扫掠长 = R·sin(ry)×2 ≈ 30cm；34.5cm 板 → ±10.6° |
| `curve_y_offset` | 0.05 | 打磨带在弧面 y 方向的居中位置（偏低 → 第一道从中间开始） |
| `tool_align_world` | true | 板面垂直时强制工具轴=世界X+（水平），防拟合平面倾斜带歪工具 |

---

## 7. 力控与接触参数（yaml）

```yaml
target_fz: -3.0            # 目标接触力(N)，试跑先小
contact_fz_threshold: -2.0 # 402 接触判定
contact_step: 0.003        # 402 步长，≈6mm/s 慢压（250mm/s 硬撞必报警）
wrench_average_count: 20   # 接触力平均窗口（原 200 滞后 ~1.6s 过冲）
adjust_dz: 0.0005          # 力控步长（0.0015 在刚性板上大幅振荡）
force_deadband: 2.0        # 力控死区
```

## 8. 测试顺序

```bash
# ① 空跑：debug_skip_force_contact: true，确认轨迹姿态/覆盖
# ② 接触试跑：debug_skip_force_contact: false，打磨机不转
ros2 topic pub --once /elite_vision_job_cmd std_msgs/msg/Int32 "data: 1"   # 拍照拿参考系（重启后必做）
ros2 topic pub --once /elite_forceapp_cmd std_msgs/msg/Int32 "data: 4"
# ③ 真磨：接打磨机电源，按纹路调 target_fz/速度
```

## 9. 常见坑（2026-08-01 实测）

| 坑 | 现象 | 处理 |
|---|---|---|
| launch 读 install yaml | 改了 src 没生效 | `colcon build --packages-select elite_polish_app` 或 cp 到 install |
| 重启后没拍照 | 轨迹离工件老远 | 重启后必须重跑命令 1（参考系在内存，重启即失） |
| 短轨迹（5点/40ms） | 发路点但机械臂不动 | 目标要长（≥480ms），否则被执行延迟吃掉 |
| 位置推算步长 | 走到"算出的表面"就停，实际还差几 cm | 固定步长一直压到力触发，别用距离推算 |
| 重力残差大 | 静止读数几十 N，接触判定/力控失真 | 多姿态拟合 tool_gravity |
| 示教器报警 | 一碰就"检测到碰撞" | 安全设置阈值调 30~50N（代码改不了这个） |
| 打磨带位置偏 | 第一道从板面中间开始 | 调 curve_y_offset（带整体上下移） |
