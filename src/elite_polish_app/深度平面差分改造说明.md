# 深度地面差分板面检测（roi_mode: depth）

## 目标

用 `/camera/depth/image_raw` 自动区分地面和打磨板，不再依赖 YOLO、固定像素框、
空治具/有工件两次差分。检测成功后仍沿用现有手眼变换、PCL 精平面拟合、IK 和
力控安全流程。

这会省掉“手工框板子、固定 ROI、空场/有板两次采集”一类现场标定，但几何定位仍需
相机内参和相机到末端的手眼外参；两者沿用相机驱动和现有 `handeye_*` 参数，不需要
每次换停车位置重新标定。

## 流程

1. 状态机到达拍照位后发布 `/elite_vision_job_cmd=1`；
2. `ysCamera3DSolver` 清空上次结果，再发布
   `/elite_polish/depth_board_request=1`；
3. `depth_board_detect_node` 处理下一帧深度图；
4. 用 `/camera/depth/camera_info` 将有效深度反投影为相机系 3D 点；
5. RANSAC 拟合画面中占比最大的地面平面；
6. 按点到地面的有符号距离提取凸起板面；
7. 形态学去噪，选择最大外轮廓并拟合四角；
8. 精修板面平面，并校验板地平行度、板面 RMS、矩形度和真实长宽；
9. 发布 `/elite_polish/depth_board_points`；
10. `ysCamera3DSolver` 用拍照位 FK×手眼外参转换到 base 系，再执行原有精 RANSAC；
11. depth 失败时回退 cluster。当前默认 `dynamic_roi_fallback_to_fixed: false`，
    depth 和 cluster 都失败就停止，不使用可能指向旧工件位置的固定框。

## 关键话题

| 话题 | 类型 | 说明 |
|---|---|---|
| `/camera/depth/image_raw` | `sensor_msgs/Image` | 原始 organized 深度图 |
| `/camera/depth/camera_info` | `sensor_msgs/CameraInfo` | 与深度图对应的内参 |
| `/elite_polish/depth_board_request` | `std_msgs/Int32` | C++ 清状态后发给深度节点的内部触发 |
| `/elite_polish/depth_board_points` | `sensor_msgs/PointCloud2` | 检出的相机系板面点；空云表示失败 |
| `/elite_polish/depth_board_info` | `std_msgs/Float32MultiArray` | 四角像素、长宽、板高和拟合质量 |
| `/elite_polish/depth_board_mask` | `sensor_msgs/Image` | 绿色板面掩膜、黄色四边形调试图 |

`depth_board_info.data` 顺序：

```text
[u0,v0,u1,v1,u2,v2,u3,v3,
 length_m,width_m,board_height_m,floor_rms_m,board_rms_m,
 parallel_angle_deg,rectangularity,valid_point_count]
```

## 当前工件参数

当前尺寸门按约 `0.34m × 0.15m` 的矩形板设置：

- 长边：`0.25 ~ 0.45m`；
- 短边：`0.10 ~ 0.25m`；
- 板面相对地面高度：`90 ~ 140mm`（现场实测约 `112.9mm`）；
- 地面和板面拟合阈值：`4mm / 3mm`；
- 板地最大夹角：`8°`。

现场拿到原始深度统计后，应优先收紧板高、长宽和 RMS 范围，减少相似物体误检。
当前改造会让参考系原点和扫掠方向跟随板面，但打磨圆弧长度、宽度和行数仍使用
`ysURForceAppControl` 的既有参数，不会仅凭检出的四角自动扩大轨迹。

## 验证

先让机械臂保持在已示教的拍照位，只触发视觉节点，不运行会自动串入打磨流程的
`/elite_forceapp_cmd data: 3`：

```bash
ros2 topic echo /elite_polish/depth_board_info
ros2 run rqt_image_view rqt_image_view /elite_polish/depth_board_mask
ros2 topic pub --once /elite_vision_job_cmd std_msgs/msg/Int32 "data: 1"
```

成功日志应依次出现：

```text
depth board OK: ...
[roi] received depth board cloud: ...
[roi] depth mode succeeded ...
[plane fit] depth PCA axis accepted ...
[plane fit] OK ...
```

实机放行前至少采集不同停车位置和板面旋转角度的样本，检查四角、尺寸、板高、
最终 base 系原点和空跑轨迹均稳定。
