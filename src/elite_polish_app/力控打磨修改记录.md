# Elite 打磨应用力控修改记录

## 1. 文档目的

本文记录 `src/elite_polish_app` 在接触搜索、SDK 闭环力控、轨迹桥接和安全退刀方面已经完成的修改，以及对应的实机验证结果。

本文以 2026-08-02 当前工作区代码和实机日志为准。状态分为：

- **已验证**：已经由实机日志证明修改生效。
- **待继续验证**：代码或参数已经修改，但尚未完成下一轮完整实机验证。
- **未处理**：只完成原因分析，尚未修改代码或参数。

## 2. 初始问题

### 2.1 位置接近导致碰撞报警

在 Git 版本 `97513f1570daf9212f64488bea0db7c4a5a77e3e` 中，机械臂使用位置轨迹逼近工件。接近速度和单步位移较大，刚性板接触后容易产生冲击，触发机械臂碰撞检测并停机。

### 2.2 首次加入 `startForceMode` 后过早进入力控

在 Git 版本 `0bd91d5cec2ff8be04e6968364e2d82f6e32e207` 附近开始接入 Elite SDK `startForceMode`。早期日志中出现：

```text
forcez_avg=-1.177 forcez_inst=-2.143
contact delta d -0.003000
force mode ENABLED
```

当时主要有以下问题：

1. 使用绝对力值判断接触，工具重力、安装倾角和传感器零漂会造成假接触。
2. 检测到接触后立即发布反向位置轨迹，同时几毫秒后启动力控，位置控制和力控存在重叠。
3. `startForceMode` 服务返回成功只代表 SDK 命令写入 socket，不代表控制器已经建立稳定闭环力。
4. 接近轨迹被高频新 goal 不断抢占，机械臂反复起步和减速，表现为长时间几乎不动。

## 3. 坐标系与力方向结论

机械臂为倾斜安装。当前工具 Z+ 轴在 base 坐标系下约为：

```text
(0.6691, 0.0000, 0.7431)
```

该方向对应世界坐标系 X+，也就是从预打磨位置朝工件逼近的方向。

Elite SDK 的 `wrench` 表示机器人施加给环境的力，和应用中传感器读到的反作用力符号相反。因此当前约定为：

- SDK `Fz > 0`：机器人沿工具 Z+/世界 X+ 压向工件。
- 应用 `relative_fz < 0`：传感器检测到工件对工具的反作用力。
- 力大时，SDK 闭环应沿世界 X- 回退。
- 力小时，SDK 闭环应沿世界 X+ 前进。

当前 `startForceMode` 使用固定参考系 `FIX`，只开放工具 Z 方向柔顺：

```text
selection_vector = [0, 0, 1, 0, 0, 0]
```

RX、RY、RZ 均不参与力控。

## 4. 接触搜索修改

### 4.1 预备位置局部去皮

机械臂到达预打磨位置并停止后：

1. 静置 `0.3 s`。
2. 采集 25 个力数据样本。
3. 计算当前姿态的局部 Z 向零点 `contact_fz_zero`。
4. 后续使用相对力判断接触：

```text
relative_fz = raw_fz - contact_fz_zero
```

该修改已经由实机日志验证。例如原始力 `raw_fz` 会随姿态出现约 `-4.8 N` 的基线，但去皮后的 `relative_fz` 可以保持在约 `0 N`，不会在未接触工件时误判。

状态：**已验证**。

### 4.2 多帧接触确认

当前接触条件为：

```text
relative_fz < -1.0 N
```

必须连续 8 个新的力传感器帧满足条件才确认接触。单个噪声尖峰不会触发状态切换。

状态：**已验证**。

### 4.3 低速、小步接近

接近阶段使用：

- 每步笛卡尔位移：`1 mm`
- 单步轨迹时间：约 `0.48 s`
- 实际接近速度：约 `2 mm/s`
- 最大搜索距离：`150 mm`
- 最大搜索时间：`90 s`

最初的 25 秒超时不足以覆盖接触搜索，先改为 70 秒、100 mm。加入工件平面拟合姿态后，实机在 100 mm 上限处仍未建立接触：

```text
travel=0.1000 relative_fz=0.134 confirm=0/8
contact search watchdog: travel=0.1000m (limit 0.1000)
```

因此将搜索行程改为 150 mm。按实测 100 mm 约需 52 秒计算，原 70 秒超时不能覆盖全部 150 mm，所以同步改为 90 秒。后续实机在约 106.9 mm 处建立接触：

```text
402 approach: travel=0.1069 relative_fz=-1.288 confirm=4/8
```

状态：**已验证**。150 mm 行程上限已使实机越过原 100 mm 保护点并在 106.9 mm 处接触工件；接近速度和力阈值未放宽。

### 4.4 接近 IK 求解容错

早期实现每个接近周期计算约 60 个插值点。TRAC-IK 单点超时就会中止，曾出现：

```text
contact approach IK failed or changed branch at point 36 (rc=-3)
```

修改后：

1. 每个周期只求解当前 1 mm 小步的终点。
2. 求解失败时依次尝试 `1.0`、`0.5`、`0.25` 倍步长。
3. 单次失败只记录警告并在下一周期重试。
4. 连续 5 个周期都失败才安全中止。

状态：**已验证**。修改后机械臂已稳定完成约 106.9 mm 接触搜索并确认接触。

## 5. 轨迹桥接修改

### 5.1 接近 goal 串行执行

原逻辑每 40 ms 发布一条持续约 0.48 s 的接近轨迹。新 goal 会抢占旧 goal，机械臂不断重新起步。实机曾在 25 秒内只移动约 2.4 mm：

```text
travel=0.0024m
time=25.00s
```

`elite_joint_trajectory_bridge` 现在识别 `frame_id == "contact_approach"`：

- 当前接近 goal 未结束时，丢弃重叠的接近 goal。
- 当前 1 mm 小步执行完成后才接受下一步。
- `force_contact_hold` 等安全保持轨迹仍可立即抢占接近轨迹。

状态：**已验证**。

### 5.2 正确解释 action 结果码

ROS 2 action 的 `CANCELED`，日志中的 code 5，在流式轨迹被新 goal 抢占时属于正常结果，不再作为控制器故障刷屏。

真正的 `ABORTED` 会输出控制器的 `error_code` 和 `error_string`。

状态：**已验证**。

## 6. 接触后切换力控

### 6.1 删除位置退让和力控重叠

确认接触后不再立即发布 `-3 mm` 反向位置轨迹。当前流程为：

1. 发布当前位置保持轨迹。
2. 保持时间 `0.25 s`。
3. 额外等待 action 完成余量 `0.20 s`。
4. 确认关节速度低于 `0.01 rad/s`。
5. 再调用 `startForceMode`。

增加 action 完成余量的原因是：实机中 `Trajectory succeeded` 比轨迹 `time_from_start` 晚约 50 ms。如果在 action 尚未完全结束时启动力控，随后的控制流程切换会干扰刚建立的力控状态。

状态：**已验证**。当前日志顺序已经变为：

```text
contact confirmed
Trajectory succeeded
force mode command sent
```

### 6.2 异步调用 SDK 服务

力控服务使用异步请求，避免在单线程 ROS executor 中同步等待 future 造成死锁。

已增加以下保护：

- 3 秒服务响应超时。
- 忽略已经失效的迟到响应。
- 异常、退刀和新命令开始前主动调用 `endForceMode`。
- 服务返回成功后仍不直接认为闭环已经稳定。

状态：**已验证**。

## 7. 力控建立验证

### 7.1 SDK 指令值与应用力值分开配置

实机发现 SDK 内部目标力与应用完成重力补偿、偏置修正和局部去皮后的 `relative_fz` 存在稳定差异：

```text
SDK 0.5 N  -> 应用 relative_fz 最终接近 0 N
SDK 2.0 N  -> 应用 relative_fz 最终约 -0.85 N
```

因此不再要求“SDK 设置 2 N，应用必须测到 -2 N”，而是分成两个参数：

```yaml
force_mode_wrench_z: 3.0
force_mode_sensor_target_fz: -1.5
```

含义分别为：

- `force_mode_wrench_z`：发送给 SDK 的内部施力目标。
- `force_mode_sensor_target_fz`：应用补偿和去皮后期望测到的实际反作用力。

### 7.2 开始切向运动前验证闭环

`startForceMode` 返回成功后，机械臂暂不启动打磨机和切向轨迹。只有满足以下条件才从子步骤 402 进入 403：

```text
relative_fz 位于 -1.5 ± 0.6 N
并连续稳定 0.5 s
```

如果 5 秒内不能建立目标力，则在开始板面横向运动之前安全退出。

实机验证日志：

```text
force-mode verification entered target band: relative_fz=-0.916
force-mode verification progress: relative_fz=-1.229
force mode VERIFIED: relative_fz=-1.539 stable_for=0.50s
```

状态：**已验证**。力控验证通过后，机械臂已经连续完成接近一整行、约 38 秒的板面运动。

## 8. 打磨过程安全监控

### 8.1 接触力过大

当相对反作用力达到或超过以下负值时立即退出力控：

```yaml
force_mode_abort_fz: -5.0
```

该阈值低于此前约 `-8 N` 附近出现的机械臂力/碰撞报警，目的是让应用先于机械臂保护停机。

### 8.2 接触丢失

当：

```text
relative_fz > -0.15 N
```

持续超过 2 秒时，判定打磨头已经离开工件，关闭力控并安全退刀。

状态：**已验证**。早期 0.5 N SDK 目标无法维持接触时，该看门狗正确触发。

### 8.3 轴向补偿上限

轴向补偿定义为：实际 TCP 与“接触偏置后的名义轨迹”之间的位移，在力控轴方向上的投影。

首行实机运行约 38 秒后达到约 10 mm，原 10 mm 上限因此触发：

```text
force-mode watchdog: axial deviation 0.0100m exceeds 0.0100m
```

上限后来调整为 15 mm。在搜索行程放宽后的实机运行中，机械臂在 106.9 mm 处成功接触，SDK 力控也在目标带内稳定 0.5 秒：

```text
force mode VERIFIED: relative_fz=-1.249 stable_for=0.50s
```

但进入子步骤 404 的第一次监控时，当前实际 TCP 相对视觉名义路径的法向偏差约为 27 mm，立即触发原 15 mm 上限：

```text
force-mode watchdog: axial deviation 0.0270m exceeds 0.0150m (relative_fz=-1.232 N)
```

该时的接触力仍正常，不属于过力或失去接触。为先继续验证完整单行轨迹，当前已按实机调试需求将上限放宽为 40 mm：

```yaml
force_mode_max_axial_deviation: 0.040
```

并每秒输出一次：

```text
force-mode monitor: relative_fz=... axial_comp=... limit=0.0400m (...%)
```

注意：“力控验证后以实际接触位置作为动态轴向基准”目前只完成了方案分析，**尚未写入代码**。当前实际生效的修改仅是将原有轴向偏差上限从 15 mm 放宽到 40 mm。

放宽轴向位置上限没有删除其他保护，以下参数仍保持不变：

- 过大力退出：`relative_fz <= -5.0 N`
- 失去接触：`relative_fz > -0.15 N` 持续 `2.0 s`
- 力控轴最大速度：`0.0005 m/s`

状态：**代码和配置已修改并编译通过，40 mm 上限待下一轮实机验证**。

## 9. 安全退刀修改

原 406 退刀轨迹写死了 base 坐标系 Y+ 方向 100 mm 侧移。发生看门狗退出后，机械臂会突然大幅横移，容易被误认为力控随机漂移。

当前退刀流程改为：

1. 关闭力控。
2. 先沿力控轴反方向，即世界 X-，退出 `30 mm`。
3. 再沿世界竖直向上方向抬升 `150 mm`。
4. 最后回 Home/预打磨位。

相关参数：

```yaml
retract_axial_distance: 0.03
retract_lift_height: 0.15
```

状态：**已验证**。原来的 Y+ 100 mm 突然侧移已删除。

## 10. 当前单行打磨设置

当前试运行改为只打磨工件宽度中心的一行：

```yaml
polishproduct_width: 0.15
polishcurve_ycount: 1
```

当 `polishcurve_ycount` 为 1 时，目标行位于宽度中心，完成第一行后直接关闭打磨机并执行安全退刀，不再进入换道和第二行。

状态：**待继续验证**。该项为 YAML 运行参数，修改后无需重新编译，但必须重启节点。

## 12. 当前状态机时序

```text
到达预打磨位置
    ↓
等待静止并局部力去皮
    ↓
沿世界 X+ 以约 2 mm/s 搜索工件
    ↓
relative_fz < -1 N，连续 8 帧确认接触
    ↓
当前位置保持 0.25 s，并等待 action 完成余量 0.20 s
    ↓
startForceMode(Fz=+3 N, 仅工具 Z 轴柔顺)
    ↓
验证应用侧 relative_fz 在 -1.5±0.6 N 内稳定 0.5 s
    ↓
开启打磨机
    ↓
执行工件宽度中心的一行轨迹
    ↓
关闭打磨机和力控
    ↓
沿世界 X- 后退 30 mm
    ↓
世界竖直向上抬升 150 mm
    ↓
返回 Home/预打磨位
```

任意阶段出现过力、失去接触、轴向补偿超限、IK 连续失败或服务超时，都会中止正常打磨流程并进入安全退出。

## 14. 工件平面 RANSAC 法向与贴面姿态

原实现使用三个 10×10 mm 小裁剪框的中心点叉乘法向，容易受单个小区域的深度噪声影响；同时 `tool_align_world: true` 会强制工具 Z+ 等于世界 X+，完全忽略工件实际倾角。

当前实现已经修改为：

1. 在 `target_box` 内使用 `SACMODEL_PERPENDICULAR_PLANE + RANSAC` 拟合工件面。
2. 约束平面法向必须位于世界 X+ 的 10° 范围内，避免把桌面等其它平面识别成工件面。
3. 对法向符号进行统一，使工具 Z+ 始终指向工件内部，不会在不同帧之间翻转。
4. 将世界竖直方向投影到拟合平面作为工具 Y 方向。
5. 由投影后的 Y 与工件法向构造工具 X，使单行扫掠方向保持接近世界 Y。
6. `tool_align_world` 默认改为 `false`，视觉输出四元数携带拟合后的工件倾角。
7. 接触搜索轴、SDK FIX 力控轴和轴向安全退刀均从该工具姿态自动获得，无需分别配置法向。

拟合结果必须同时通过以下质量门槛：

| 参数 | 当前值 | 含义 |
|---|---:|---|
| `plane_fit_distance_threshold` | `0.003 m` | RANSAC 内点距离阈值 |
| `plane_fit_max_iterations` | `1000` | 最大迭代次数 |
| `plane_fit_min_inliers` | `1000` | 最小内点数量 |
| `plane_fit_min_inlier_ratio` | `0.15` | 内点占目标 ROI 的最小比例 |
| `plane_fit_max_rms` | `0.0025 m` | 内点距离 RMS 上限 |
| `plane_fit_max_normal_angle_deg` | `10°` | 相对世界 X+ 的最大法向夹角 |

任一门槛不满足时，本次视觉任务返回失败，不会把不可信姿态发送给机械臂。成功时保存 `plane_fit_inliers.pcd`，并输出：

```text
[plane fit] OK: inliers=... ratio=... RMS=... angle_to_world_x=...deg
[plane fit] normal_base=(...) origin_base=(...)
```

已增加确定性的合成点云测试 `test/test_pcl_plane_fit.cpp`：输入相对世界 X+ 倾斜 3° 的平面并混入 500 个离群点。当前测试结果为内点率 98.0%、RMS 0.283 mm，最终工具 Z 与合成真实法向的误差低于输出精度，并且法向符号保持朝世界 X+。

最新实机运行中，拟合姿态最终传递到接触和 SDK 力控轴：

```text
axis_base=(0.6923,0.0368,0.7207)
```

## 17. 打磨头 IO 开关修改

打磨头开关已改为驱动提供的 `SetIO` 服务：

```text
/io_and_status_controller/set_io
eli_common_interface/srv/SetIO
```

开启命令对应：

```yaml
fun: 2
pin: 7
state: true
```

关闭命令对应：

```yaml
fun: 2
pin: 7
state: false
```

代码修改包括：

1. 恢复子步骤 403 中的 `ysPolishTool_Open()` 调用，力控验证通过后自动开启打磨头。
2. 子步骤 405 保持调用 `ysPolishTool_Close()`，正常完成或安全中止时关闭打磨头。
3. 原实现的 `pin=0` 改为 `pin=7`，`fun` 改为枚举 `FUN_SET_CONFIGURE_OUT`，其值为 2。
4. 不再在每次调用时创建临时 ROS 节点和临时客户端；改为 `ysURForceAppControl` 节点持有长期 `SetIO` 客户端，避免异步请求发出后客户端立即被销毁。
5. 增加异步响应检查：服务返回 `success=true` 时输出 confirmed 日志，拒绝或异常时输出 ERROR。
